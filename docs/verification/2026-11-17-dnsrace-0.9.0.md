# dnsrace 0.9.0 verification

Date: 2026-11-17
Target: dnsrace 0.9.0, desktop plus Android 8.0+ (API 26+)

## Environment

- Linux, KDE Plasma on a native Wayland session.
- Rust 1.100.0, edition 2024, eframe/egui 0.37.
- Desktop gates were run on Linux.
- Android toolchain: JDK 17 at `~/Android/jdk17`, SDK platform 36, build-tools 36.0.0,
  cargo-apk 0.10. The release workflow builds the APK with NDK 30.0.16248370.

## Static gates

Commands:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
cargo build --release --locked
```

Results:

- `cargo fmt --all -- --check`: clean.
- `cargo clippy --workspace --all-targets --locked -- -D warnings`: clean.
- `cargo test --workspace --locked`: 267 unit tests and 9 engine integration tests passed,
  0 failed.
- `cargo build --release --locked`: succeeds.

## Packaging tasks

The two former shell helpers are replaced by the Rust `xtask` member.

```sh
cargo run -p xtask -- icons
cargo run -p xtask -- appimage 0.9.0 x86_64 target/release/dnsrace <output-dir>
```

- `icons` regenerated all desktop PNGs, the ICO and every Android mipmap without changing the
  tracked files.
- `appimage` built `dnsrace-0.9.0-x86_64.AppImage` (7.8 MB) and its SHA-256 sidecar in a
  temporary output directory. The desktop file and AppStream metadata validated.
- The release workflow uses the same task; no shell scripts remain in the repository.

## Desktop runtime

- Native Wayland launched and rendered every page, including the Arabic right-to-left layout.
- Arabic screenshots checked the rail, cards, tables, Settings and the custom-resolver dialog
  for clipping or overlap.
- X11 fallback was checked with a stale Wayland display and `DISPLAY=:1`:
  `dnsrace: Wayland display is unavailable; falling back to X11` was logged, and
  `xprop -display :1 -root _NET_CLIENT_LIST` listed the new window.
- Wayland remains preferred when both Wayland and XWayland are available.

## CLI

- `dnsrace --cli --version` printed `dnsrace 0.9.0`.
- `dnsrace --cli --list`, `--help`, a live Quick run, and JSON/CSV export were exercised.
- Progress goes to stderr, the ranked table to stdout.

## Updates

- Version comparison and checksum parsing have unit tests.
- A live in-place update could not be exercised because no release newer than 0.9.0 existed
  before tagging. The download path verifies the asset against the release
  `SHA256SUMS.txt` before any install step; Android opens the APK download link instead of
  self-installing.

## Android

- The release workflow builds the universal debug-key APK with cargo-apk 0.10 and NDK
  30.0.16248370, then checks the manifest and native ABIs.
- A local APK build was attempted. The NDK package installation was incomplete in this
  environment; the desktop release gates and release workflow remain the authoritative APK
  build. Device testing from the 0.8.0 run is not a substitute for testing the 0.9.0 APK.

## Limitations

- Android self-update requires browser download and system installer confirmation.
- In-place Linux update applies to the AppImage; other Linux layouts open the release page.
- Windows release builds use the GUI subsystem, so the CLI is intended for Linux/macOS
  release builds.
- macOS builds remain ad-hoc signed.
