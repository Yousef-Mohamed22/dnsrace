# dnsrace 0.8.0 Adaptive Desktop + Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship dnsrace 0.8.0 with a rebuilt adaptive desktop/Android GUI, benchmark profiles and insights, a guided Android Private DNS experience, a new icon, fixed correctness bugs, and full button-level verification.

**Architecture:** Replace `src/gui.rs` with a `src/gui/` module split into state, actions, backend, theme, components, desktop/mobile shells, and pages. Keep the networking engine, extend it with profiles, depth, environment injection, and richer `Row` metadata. Add pure `profile`, `recommend`, and `android_guide` modules. Keep Android 100% Rust through eframe/winit's native activity, JNI wrappers for platform services, and a `cargo-apk` universal APK.

**Tech Stack:** Rust 1.99.1, edition 2024, eframe/egui 0.37, egui_extras 0.37, tokio 1.54, rustls 0.23, ureq 2.12, serde, egui_kittest 0.37, jni, cargo-apk 0.10, Android SDK 36 / NDK 27, Waydroid.

**Spec:** `docs/superpowers/specs/2026-11-09-dnsrace-0.8.0-design.md`

## Global Constraints

- Version is **0.8.0** everywhere: Cargo.toml, Cargo.lock, README, CHANGELOG, AppStream, release notes, Windows metadata, Android versionName.
- Rust **1.99.1**, edition **2024**, `rust-toolchain.toml` unchanged.
- 100% Rust application code. No Kotlin, Java, VpnService, root, local proxy, or background service.
- Android **minSdk 26**, **targetSdk 36**, **compileSdk 36**, ABIs arm64-v8a, armeabi-v7a, x86_64.
- No iOS or other Apple phone targets. macOS desktop support stays.
- Desktop apply/revert stays on Linux, Windows, and macOS. Android is benchmark + guide only.
- Android 9+ (API 28+) gets Private DNS guidance. Android 8.0–8.1 (API 26–27) gets Wi-Fi DNS guidance.
- 0.8.0 Android artifact is a **debug-signed** universal APK; release workflow supports a real keystore later.
- Existing settings, history, applied state, custom resolvers, reports, and all eight themes remain backward compatible.
- `Row.note: Note` keeps its name and serialized health meaning; provider text is `Row.description`.
- Runs stay single-protocol. Best encrypted is computed only from measured encrypted rows.
- Desktop primary apply action targets the fastest applicable **plain** resolver; encrypted selections are not silently substituted.
- Android sharing is text-only (`ACTION_SEND`); no FileProvider, content provider, or storage permission.
- No git repository exists. Do not initialize one unless asked. Use the verification checkpoint at the end of each task instead of commits; if a repo is initialized later, commit each completed task.
- Every task ends with `cargo fmt --all -- --check` and the focused test command; run the broader suite at phase boundaries.

## Review Focus

These are the failure modes most likely to hurt a user and are not obvious from any single feature task:

1. **Android 8 sees a dead Private DNS action.** An API 26–27 user must get the Wi-Fi DNS guide and must never see a button that opens a nonexistent Private DNS screen. Test: `android_guide` API 26 matrix plus a mobile render test asserting the Private DNS action is absent.
2. **A plain/custom resolver claims a DoT hostname it does not have.** A missing hostname must produce the “benchmark DoT” state, not a copyable wrong value. Test: `android_guide` missing-hostname and custom-row cases.
3. **An old config/history/report file breaks or loses data after the schema change.** Missing new fields must load with defaults; `Row.note` must keep its old JSON meaning. Test: config/history/report deserialization fixtures from 0.7-shaped JSON.
4. **A DNSSEC-unverifiable answer is shown as “bogus accepted”.** NXDOMAIN, REFUSED, and timeouts must become `None`/unknown, not block a resolver. Test: rcode matrix in `bench`.
5. **A mobile button is clipped or too small at 390×844 with safe-area insets.** Primary controls must remain reachable and at least 44–48 points. Test: mobile kittest render at 390×844 and component `Response.rect` height assertions.

- [x] **Step 3: Implement the model**

Rules: `overall` is the chosen recommendable row if provided, otherwise the fastest recommendable row. `best_plain` filters `is_plain() && plain_ip().is_some()`. `best_encrypted` filters `!is_plain()` from this run. `current` matches `current_dns` against row addresses; only compare delta against `overall`. `close_call_ms` is the absolute score difference between the top two recommendable rows if `<= max(2.0, 0.10 * top.score)`. `delta_ms = current.score - overall.score`; `delta_pct = delta_ms / current.score * 100.0` when current score > 0.
