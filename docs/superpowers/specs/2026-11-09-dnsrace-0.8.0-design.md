# dnsrace 0.8.0 — Adaptive Desktop + Android Design

- **Date:** 2026-11-09
- **Status:** Draft for approval
- **Chosen approach:** A — adaptive rebuild
- **Target version:** 0.8.0
- **Toolchain:** Rust 1.99.1, edition 2024
- **Platforms:** Linux, Windows, macOS desktop; Android 8.0+ (API 26+). No iOS or other Apple phone targets.

## 1. Intent

dnsrace 0.7.0 proves the engine works but looks and behaves like a desktop utility with an Android port bolted on. 0.8.0 should feel like a new product: a clean, coherent interface on desktop and phone, a benchmark that explains its recommendation, and an Android experience that is honest about what Android allows — measure resolvers, then guide the user through setting Private DNS (Android 9+) or Wi-Fi DNS (Android 8.0–8.1).

This is a large release: the GUI is rebuilt around an adaptive shell, the engine gains test profiles and richer result metadata, Android becomes a first-class 100% Rust target, every reported bug is fixed, and the app gets a new identity.

## 2. Goals

1. **A professional, uncluttered interface** on desktop and Android with one visual language and two layouts.
2. **Touch-sized Android controls** (minimum 44–48 logical points) and layouts that work in portrait and landscape, including display cutouts and system bars.
3. **Benchmark-only Android with guided setup**:
   - Android 9+ (API 28+): copy the winner's DoT hostname and open Private DNS settings directly.
   - Android 8.0–8.1 (API 26–27): Private DNS does not exist; guide the user to per-network Wi-Fi DNS with plain addresses.
   - No VpnService, root, Kotlin, Java, or one-tap DNS switching.
4. **More useful results**: test profiles, favourites, recommendation deltas and close-call warnings, best encrypted resolver, detailed metrics, and history trends.
5. **Fix the known correctness and reliability bugs** (DNS reply validation, DNSSEC classification, categories, atomic config writes, export collisions, Android paths).
6. **A new app icon and visual identity** across desktop, macOS, Windows, and Android adaptive icons.
7. **Verification that every button works**, not just that the app compiles.
8. **A visibly large 0.8.0 release** with Android artifacts, updated documentation, and complete release notes.

## 3. Non-goals

- iOS, iPadOS, or any Apple phone target.
- Applying or reverting DNS automatically on Android.
- A `VpnService`, local DNS proxy, root shell, or background service on Android.
- Kotlin or Java application code. All application logic remains Rust.
- Rewriting the measurement engine or switching GUI frameworks.
- A web UI, CLI mode, telemetry, accounts, or cloud sync.
- Replacing egui/eframe with another toolkit.

## 4. Anti-goals

- A mobile layout that is only a shrunken desktop window.
- Tiny tap targets, horizontal scrolling tables, or desktop-style dialogs on a phone.
- Pretending Android can be changed the way desktop DNS can.
- Hiding limitations behind generic error messages.
- Shipping a "new look" that is only a recolour while the old layout remains.
- Declaring Android tested without a real build or a device/emulator run.

## 5. Constraints and current state

- Cargo.toml pins `rust-version = "1.99.1"` and `rust-toolchain.toml` pins the same.
- `src/gui.rs` is 3,332 lines; state, effects, pages, dialogs, and widgets are mixed together.
- `eframe` 0.37 uses `fn logic(...)` and `fn ui(...)`, not the older `update`.
- `eframe` 0.37 supports Android through `NativeOptions::android_app`, `winit`'s `AndroidApp`, and the `android-native-activity` feature.
- `#![forbid(unsafe_code)]` is currently crate-wide. Android requires an exported entry point and JNI; the attribute must become `cfg_attr(not(target_os = "android"), forbid(unsafe_code))`.
- The local machine has Rust 1.99.1, `adb`, ImageMagick, and `rsvg-convert`; it has no Android SDK or NDK yet, but **Waydroid is installed** (currently stopped) and will be used for the Android runtime pass. Waydroid covers the API 28+ Private DNS path, not the Android 8.0–8.1 branch.
- The existing baseline is 98 unit tests plus 9 engine integration tests, all passing.
- `cargo-apk` 0.10 is the packaging tool (deprecated upstream in favour of `xbuild`, but stable and proven with eframe). It builds one APK containing every configured Rust target.
- `egui_kittest` 0.37 exists and matches egui/eframe 0.37.
- Android Private DNS is only user-configurable from Android 9 (API 28). Android 8.0/8.1 need a different guide; this is a product requirement, not a limitation to hide.

## 6. Approaches considered

### A. Adaptive rebuild — chosen

Extract state/effects out of `gui.rs`, introduce an action/effect boundary, build a new adaptive shell with desktop and mobile layouts, then lay the redesigned pages and features on top. The engine stays and gains focused extensions. Android uses the same Rust app and eframe entry point.

**Why chosen:** it delivers the requested clean professional result on both form factors, creates a structure where every button is testable, and avoids carrying the desktop-first layout into Android.

### B. Refactor in place — rejected

Keep the current screen structure, restyle it, add tabs on top, and bolt on Android guidance.

**Rejected because:** it is faster but produces a recoloured 0.7.x. Mobile would remain a squeezed desktop, the 3,332-line file would keep growing, and button testing would remain difficult.

### C. Workspace split — rejected

Move the engine into `dnsrace-core`, rebuild the GUI as a separate crate, and give Android its own frontend crate.

**Rejected because:** the boundaries are attractive but the churn is disproportionate. It touches nearly every file, adds packaging/CI complexity, and delays the features that make 0.8.0 feel large.

## 7. Product design

### 7.1 Visual language: "Signal"

A calm technical identity built around clarity and measured data.

- **Colour:** deep ink surfaces (`#0B1220` background, `#111A2B` surface, `#16243A` elevated), cool borders (`#26364F`), bright text (`#E8EEF8`), muted text (`#93A4BD`), cyan accent (`#38BDF8`), mint success (`#34D399`), amber warning (`#FBBF24`), rose danger (`#FB7185`).
- **Light theme:** `#F6F8FC` background, white surfaces, `#D9E2F0` borders, `#182133` text, same accent/success/warning/danger hues tuned for contrast.
- **Existing presets:** all eight existing theme choices remain available so no user loses a setting. The default Dark and Light palettes are rebuilt on the new tokens; the other presets inherit the new spacing, typography, and component shapes.
- **Typography:** bundle Inter (UI) and JetBrains Mono (addresses, latency values, hostnames) under `assets/fonts/` with their OFL licences. Fall back to egui's bundled fonts if an asset is unavailable. Sizes: 12 caption, 13 body-small, 14 body, 16 section, 20 page title, 28 hero metric. No text below 11 logical points.
- **Shape:** 10–14 point radii, 1 px borders, flat surfaces. No drop shadows except modal elevation; no decorative gradients in the app chrome.
- **Spacing:** 4 px base unit; 8/12/16/24/32 steps. Desktop control height 40; mobile control height 48; icon buttons 44×44 minimum.
- **Icons:** a small hand-drawn line set (18/20 px, 1.75 px stroke, rounded caps) for navigation and actions. No icon font dependency.
- **Motion:** short fades/hover states only; no looping animation except the progress spinner.

### 7.2 Desktop shell

- Default window 1280×840; minimum 900×600.
- Left navigation rail, 232 px: brand mark and version at the top, primary **Run benchmark** action, destinations **Overview**, **Servers**, **History**, **Settings**, and a bottom network-status card.
- Main content area: contextual top bar (page title, one-line description, page actions), then a scrollable page with a maximum content width.
- **Overview:** current-DNS card, recommendation card, run-profile control, progress card, and the top results. One obvious primary action; secondary actions are quieter.
- **Servers:** search/filter toolbar, selection count, server table, and a right-hand detail pane when a row is selected. The table remains the dense desktop view.
- **History:** a run list with a sparkline trend strip and a detail pane for the selected run; reopen, export, delete, and clear actions live here.
- **Settings:** full page with grouped cards, not a floating window. Appearance, benchmark defaults, steering, export location, data management, Android-only section when applicable, and About.
- **Dialogs:** only for confirmation and focused editing: custom resolver editor, apply confirmation, revert confirmation, and the Android setup sheet. Escape and a visible Cancel close them.
- **Responsive behaviour:** below 980 px the rail narrows to icon + label; below 720 px the app switches to the mobile shell, even on desktop. This keeps small laptop windows usable.

### 7.3 Android shell

- Top app bar: brand mark, page title, and a compact status chip (network/current DNS state).
- Bottom navigation, 64 dp: **Benchmark**, **Servers**, **History**, **Settings**. Each destination is a 56×56 minimum target with icon and label.
- Content: 16 dp page padding, 12 dp card gaps, vertical scrolling, no horizontal table.
- **Benchmark:** current network card (or a clear "Current DNS unavailable" state), profile chips, a full-width 56 dp **Start benchmark** button, progress card, recommendation card, and result cards. Result cards show provider, endpoint, score, cached/uncached latency, security pill, and a star. Tapping a card opens a detail sheet.
- **Servers:** search field, horizontally scrollable filter chips, server cards with a 48 dp checkbox/star, and a sticky **Test selected** action above the bottom navigation. The catalogue can also be tested in full from the overflow/menu.
- **History:** run cards with winner, time, profile, and trend; tapping opens a detail sheet with reopen and share actions.
- **Settings:** grouped list rows with 48 dp targets. The Android section explains the platform limitation and offers **Set up Private DNS**.
- **Bottom sheets:** rounded top corners, drag handle, 48 dp close target, scrollable content, full-width action buttons. On landscape/tablet widths, the sheet becomes a centred modal with a maximum width.
- **Safe areas:** respect `egui`'s `SafeAreaInsets` for status/navigation bars and display cutouts. All primary actions stay reachable without scrolling under the bars.
- **Back/escape:** Escape closes the topmost sheet/dialog before navigating away.

### 7.4 Pages, navigation, and state

The app has four destinations on both platforms. `About` lives inside Settings, with a compact version card and the new icon. The current separate About/History/Settings windows disappear.

Navigation state is part of the app state, so the desktop and mobile shells render the same page models with different chrome. Search, filters, selection, sort, and open sheets survive page switches and window resizing.

## 8. Features

### 8.1 Test profiles

A profile control appears on Overview/Benchmark and in Settings:

| Profile | Timeout | Jobs | Repeat | Cached rounds | Random lookups |
|---|---:|---:|---:|---:|---:|
| Quick | 700 ms | 24 | 1 | 2 | 3 |
| Balanced (default) | 1000 ms | 16 | 1 | 3 | 5 |
| Thorough | 1500 ms | 16 | 2 | 4 | 8 |
| Custom | user values | user values | user values | user values | user values |

- Choosing a profile writes timeout, jobs, repeat, cached rounds, and random lookups into settings. Editing any advanced value switches the profile to Custom.
- `TestDepth { cached_rounds, random_lookups }` is built from those persisted settings; `bench::full_test` uses it instead of fixed constants.
- The selected profile and depth are saved and shown in history entries and reports.
- Android defaults to Balanced and the DoT protocol; desktop defaults to Balanced and UDP.

### 8.2 Favourites

- `Settings.favorites: BTreeSet<String>` stores candidate IDs.
- A star toggles a favourite from the server list and result cards; the state persists.
- A **Favourites** filter chip and a **Test favourites** action appear when at least one favourite exists. If none exist, the action is disabled with an explanation.
- Favourites are local only; no accounts or sync.

### 8.3 Recommendation insights

A pure `recommend` module computes:

- `overall`: the chosen recommendable resolver (user selection or the fastest measured).
- `best_plain`: the fastest recommendable plain resolver that desktop can apply.
- `best_encrypted`: the fastest recommendable DoT/DoH resolver **from rows measured in this run**. Runs stay single-protocol, so a UDP run has no encrypted winner; the UI then offers "Run DoT servers to compare encrypted resolvers" instead of inventing one from metadata.
- **Comparison with current DNS** when a measured row matches a detected current-DNS address: `12.4 ms faster (18%)`, `slower than your current DNS`, or `same as current` with a minimum meaningful-delta threshold.
- **Close call** when the top two recommendable resolvers are within `max(2 ms, 10%)`: "The top two are within 1.8 ms; either is a good choice."
- Plain-language reasons: fastest measured, DNSSEC validated, no NXDOMAIN hijacking, low jitter, encrypted transport.
- Platform-specific action target:
  - Desktop: the primary **Use this resolver** action targets `best_plain` (or the user's selected plain row). If the user selects an encrypted row, applying is disabled with an explanation; the card never silently substitutes a different provider.
  - Android: the primary **Set up this resolver** action targets the winner's DoT hostname via the guide. When the selected row is plain or DoH, provider metadata may supply that hostname, but it is labelled **"provider's DoT hostname — not measured in this run"** and the guide offers a DoT benchmark.
- A warning when the overall winner is encrypted only: desktop cannot apply it; Android needs Private DNS; the card still shows the encrypted result separately.

The Overview card shows the overall winner, score, deltas, security, the best applicable resolver on desktop, the best encrypted resolver when measured, and the platform-appropriate action.

### 8.4 History trends

- History keeps the existing 20-run limit.
- A sparkline shows the winner score over the last 10 runs (lower is better), with a tooltip per point and a "no trend yet" state.
- History entries now record the profile name and depth.
- History supports reopen, export (desktop), share report as text (Android), delete one, and clear all.
- Android sharing is text-only through `ACTION_SEND`: the JSON/CSV report or a readable HTML-to-text summary. No content provider, FileProvider, or temporary file is required.

### 8.5 Detailed resolver metrics

A detail view shows all measured data:

- Provider, label, category, endpoint, transport, website.
- Cached median, mean, min, p95, p99, max, jitter.
- Uncached median.
- Timeouts and health note.
- DNSSEC AD result and bogus-signature result with plain-language explanations.
- Current-DNS match and whether it can be applied.
- Actions: choose as recommendation, toggle favourite, copy endpoint, open provider website, and (desktop) apply.

Desktop uses the right detail pane; Android uses a bottom sheet. The same data model feeds both.

### 8.6 Android Private DNS guide

A pure `android_guide` module builds the guide from the selected row, detected API level, catalogue, and provider metadata.

**Android 9+ (API 28+):**

1. Copy the resolver's DoT hostname (for example `cloudflare-dns.com`).
2. Open **Settings → Network & internet → Private DNS** with a best-effort intent.
3. Choose **Private DNS provider hostname** and paste the hostname.
4. Save, then re-run dnsrace to confirm the result.

The guide shows the hostname in a monospace, selectable field, a 48 dp **Copy hostname** button, and an **Open Private DNS settings** button. If the selected resolver has no DoT hostname, the guide says so and offers **Benchmark DoT servers instead**.

**Android 8.0–8.1 (API 26–27):**

Private DNS does not exist. The guide explains per-network Wi-Fi DNS:

1. Open Wi-Fi settings.
2. Long-press the connected network and choose **Modify network → Advanced options**.
3. Change **IP settings** to **Static**.
4. Enter the resolver's IPv4 addresses in DNS 1/DNS 2.
5. Save and reconnect, then re-run dnsrace.

The guide shows plain IPv4 addresses from the selected row, or the provider's known plain addresses from the catalogue. If only a DoT/DoH result exists, it explains that a plain-DNS benchmark is needed and offers to switch protocol.

**Both versions:**

- A visible note: "Android does not let dnsrace change DNS automatically. This guide only opens settings and copies values."
- All copy/open/share operations go through a testable `AndroidHost` trait. Real failures fall back to written steps and a notice; they never crash the app.
- Clipboard uses Android's `ClipboardManager` through JNI when egui's clipboard integration is unavailable.
- On Android 13+ the system may refuse the intent; the manual steps remain visible.

### 8.7 Existing features retained

- UDP/TCP/DoT/DoH benchmarking and the quick-scan/full-test pipeline.
- System DNS detection on desktop; best-effort detection on Android.
- Current-DNS comparison, `IN USE` badge, Test current DNS, copy, refresh.
- Apply/revert on Linux, Windows, and macOS with confirmations and saved previous state.
- Custom resolvers, steering checks, history, reports, eight themes, keyboard shortcuts.
- No telemetry, accounts, or background service.

## 9. Android platform design

### 9.1 Entry point and crates

- `src/lib.rs` changes `#![forbid(unsafe_code)]` to `#![cfg_attr(not(target_os = "android"), forbid(unsafe_code))]`.
- `src/main.rs` keeps the desktop entry point; `src/android_entry.rs` (or an `android` module) provides:
  - `#[cfg(target_os = "android")] #[unsafe(no_mangle)] fn android_main(app: AndroidApp)`.
  - It initialises Android paths, builds the real backend/host, sets `NativeOptions.android_app`, and calls `eframe::run_native`.
- `[lib] crate-type = ["rlib", "cdylib"]` so `cargo-apk` can package the library while tests and the desktop binary still use the rlib.
- Android target dependencies:
  - `eframe` with `glow`, `default_fonts`, `accesskit`, `clipboard`, `links`, `system_fonts`, and `android-native-activity` (GLES is the safest choice for Android 8+).
  - `winit` 0.30 for `AndroidApp`.
  - `jni` for clipboard, intents, `Build.VERSION.SDK_INT`, and optional `ConnectivityManager` detection.
- Unsafe code is confined to the Android entry point and thin JNI wrappers. Public app code remains safe Rust.

### 9.2 Data paths

- On Android, `AndroidApp::internal_data_path()` is the config directory. Reports are shared as text, so no external file path or storage permission is needed.
- `config::init_paths(config_dir, export_dir)` stores an application-wide override in a `OnceLock`. It is initialised before the first frame.
- Desktop keeps the existing `DNSRACE_CONFIG_DIR` override and `dirs` fallbacks.
- This fixes the current `"."` fallback on Android, which can point at an unwritable install directory.

### 9.3 Current DNS and capabilities

- `Capabilities { platform, can_apply_dns, can_detect_system_dns, can_export_files, default_protocol, android_sdk }` is computed at startup and injected into the app.
- Android detection uses `ConnectivityManager`/`LinkProperties` through JNI (best effort, `ACCESS_NETWORK_STATE`). If it fails, the UI says "Current DNS unavailable on this device" and hides comparison; benchmarking still works.
- `RunRequest` gains `environment: Option<SystemInfo>`. On Android the app passes the detected environment (possibly empty) so the engine never falls back to Linux commands. On desktop `None` keeps the existing detection path.
- `platform_name()` returns "Android" on Android. Apply/revert capabilities are false; the UI never renders those actions.

### 9.4 Android manifest and packaging

- `[package.metadata.android]`:
  - package `io.github.yousef_mohamed22.dnsrace`
  - label `dnsrace`
  - `apk_name = "dnsrace"` (release workflow renames it with the version)
  - `build_targets = ["armv7-linux-androideabi", "aarch64-linux-android", "x86_64-linux-android"]`
  - minSdk 26, targetSdk 36, compileSdk 36
  - `resources = "packaging/android/res"`
  - application icon `@mipmap/ic_launcher`
  - `INTERNET` and `ACCESS_NETWORK_STATE` permissions only
  - native activity, portrait and landscape supported, resizeable, `extract_native_libs = false`
- Adaptive icon resources for API 26+ plus legacy mipmap PNGs for all densities; monochrome icon for Android 13 themed icons.
- **0.8.0 ships a debug-signed APK** for local installation and Waydroid testing. The release workflow is written to use a real keystore later through CI secrets (`CARGO_APK_RELEASE_KEYSTORE`, `CARGO_APK_RELEASE_KEYSTORE_PASSWORD`, plus key alias/password); release builds fail clearly if that keystore is requested but missing.
- The Android artifact is a universal APK named `dnsrace-0.8.0-android-debug.apk`, containing arm64-v8a, armeabi-v7a, and x86_64. The x86_64 ABI is required for Waydroid.

### 9.5 Android behaviour boundaries

- No `VpnService`, no local resolver, no root, no background service.
- No automatic configuration writes. The only system interaction is opening Settings and copying/sharing text.
- Android 8.0/8.1 gets the Wi-Fi DNS guide, not a broken Private DNS button.
- `adb` is used only for development/QA, never by the app.

## 10. Architecture

### 10.1 Module layout

`src/gui.rs` becomes a directory module:

```
src/gui/
  mod.rs          app lifecycle, eframe::App, real startup
  app.rs          App state container and dispatch
  actions.rs      UiAction and effect requests
  state.rs        AppState, Page, LayoutMode, filters, modals
  backend.rs      Backend trait, real backend, test backend
  theme.rs        design tokens, palettes, fonts, style setup
  components.rs   buttons, cards, pills, metric tiles, inputs, sheets
  icons.rs        painted line icons
  desktop.rs      desktop shell
  mobile.rs       Android/compact shell
  pages/
    benchmark.rs
    servers.rs
    history.rs
    settings.rs
  modals.rs       custom resolver, apply/revert confirmation, detail/guide sheet
  tests/          kittest UI tests
```

New crate-level modules:

- `src/recommend.rs` — pure recommendation/insight model.
- `src/android.rs` — `AndroidHost` trait, real JNI implementation, fake for tests.
- `src/android_guide.rs` — pure guide content for API 26/28+ and all resolver kinds.

### 10.2 Rendering and actions

- Page renderers take `&mut AppState` and `&ViewContext` (capabilities, layout, version, selected row) and push `UiAction`s into a queue. They do no I/O and start no threads.
- `App::dispatch(action)` is the only place that mutates settings files, starts detection/runs, applies/reverts, exports, copies, opens intents, or navigates.
- `Backend` isolates effects:

```rust
trait Backend {
    fn start_detection(&self) -> Receiver<SystemInfo>;
    fn start_run(&self, request: RunRequest) -> Receiver<RunEvent>;
    fn apply(&self, addresses: Vec<IpAddr>) -> Receiver<Result<AppliedDns, String>>;
    fn revert(&self, applied: AppliedDns) -> Receiver<Result<(), String>>;
    fn export(&self, format: ReportFormat, result: &RunResult) -> Result<PathBuf, String>;
    fn copy(&self, text: &str) -> Result<(), String>;
    fn open_link(&self, url: &str) -> Result<(), String>;
    fn share_text(&self, subject: &str, text: &str) -> Result<(), String>;
    fn android(&self) -> Option<&dyn AndroidHost>;
}
```

- `RealBackend` owns the existing thread/channel code. `TestBackend` records calls, returns empty channels or canned results, and can simulate copy/open/share failures.
- `AndroidHost` methods (`copy_text`, `open_private_dns_settings`, `open_wifi_settings`, `share_text`) each return `Result<(), String>`. `App::dispatch` converts a failure into a visible notice and keeps the manual guide steps on screen.
- This boundary is what makes "click every button without starting a network run" possible.

### 10.3 Layout selection

- `LayoutMode::Mobile` when `Capabilities.platform == Android` or available width < 720 px; otherwise `LayoutMode::Desktop`.
- `ViewContext` carries the mode and safe-area insets. Both shells render the same page state and actions.
- Desktop table and mobile cards consume the same filtered/sorted row list.

### 10.4 State additions

`AppState` retains existing fields and adds:

- `page: Page` (`Overview`, `Servers`, `History`, `Settings`).
- `profile: Profile`.
- `favorites` is read from settings; a derived favourite filter is UI state.
- `selected_row: Option<String>` for details.
- `guide: Option<AndroidGuide>`.
- `confirm: Option<ConfirmKind>` for apply/revert/delete/clear.
- `custom_draft`, `pending_apply`, notices, and run channels as today.
- `last_action`/action queue only in tests, not production.

### 10.5 Settings and migration

- `Settings` gains `profile: Profile`, `favorites: BTreeSet<String>`, `cached_rounds: usize`, and `random_lookups: usize` with serde defaults.
- `timeout_ms`, `jobs`, and `repeat` remain the persisted outer-run values. `repeat` keeps its existing meaning (outer full-test rounds); `cached_rounds` replaces the fixed `ROUNDS = 3` inner loop, and `random_lookups` replaces the fixed `RANDOM_LOOKUPS = 5`.
- Choosing a preset writes all five values. Editing any advanced value switches the profile to Custom. Custom values survive restart because they are stored in `Settings`, not only in the profile label.
- Existing settings files load unchanged. Missing fields get Balanced defaults. If an old file has non-default timeout/jobs/repeat values, it loads as Custom rather than mislabelling those values as Balanced.
- Removed theme presets are not planned; all eight remain.
- `RunResult` gains `profile: Option<Profile>` and `depth: Option<TestDepth>` additively. `RunRequest` carries the same values; the engine copies them into the result so exports and history use the values of that run, not the current settings.
- `HistoryEntry` gains `profile: Option<Profile>` and `depth: Option<TestDepth>` with defaults for old history, derived from the result when saving.
- JSON/CSV/HTML reports add the new fields additively; existing fields stay stable.

### 10.6 Engine and result changes

- `RunRequest` gains `environment: Option<SystemInfo>`, `profile: Profile`, and `depth: TestDepth`.
- `RunResult` gains `profile` and `depth` additively; `RunEvent::Finished`/`Cancelled` results carry them.
- `bench::full_test` takes `TestDepth` and uses its round/lookup counts.
- `Row` gains:
  - `category: Category` with serde default General (fixes category filtering for custom/system rows).
  - `description: String` and `website: String` from the candidate.
  - `dot_host: Option<String>` for the Android guide.
- The existing `Row.note: Note` health verdict (`Ok`/`Hijacks`/`Unreliable`) keeps its name, meaning, and serialized shape. Provider explanatory text is `description`, not `note`, so old history JSON and report scripts continue to parse. No serde rename or alias is required.
- `providers::dot_host_for(provider, label)` resolves a DoT hostname from provider metadata when the row itself is plain or DoH.
- `engine::apply_addresses` and apply/revert semantics are unchanged on desktop.

## 11. Bug fixes

1. **Reject replies without a question.** `dns::parse_reply_for` currently accepts a reply with `question == None`. It must require an echoed question matching name, type, and class. Add tests for zero-question and mismatched-question replies.
2. **Fix DNSSEC bogus classification.** A resolver is marked as accepting a bogus signature only when it returns `NOERROR` for `dnssec-failed.org`. `SERVFAIL` means correctly rejected. `NXDOMAIN`, `REFUSED`, timeouts, and other errors mean "unknown", not "accepted". Add a full rcode matrix test.
3. **Store the row category.** `Row` carries `Category` so system/custom/filtered results no longer fall back to General. Use it everywhere instead of the provider-metadata lookup.
4. **Make config writes crash-safe on Windows.** Write a temp file, flush it, then replace atomically. On Windows, first try rename; if the target exists, move the old file to a `.bak`, rename the new file into place, and restore the backup if the final rename fails. Remove the backup only after success. Add replacement tests.
5. **Never overwrite an export.** Replace the 10,000-suffix cap with an atomic `create_new` writer that retries suffixes until it reserves a unique path. The default suggestion and the actual write both use it.
6. **Fix Android paths.** Initialise config/export paths from `AndroidApp` data directories instead of falling back to `"."`.
7. **Report Android as Android.** `platform_name()` and About/Settings display "Android", not "this platform".
8. **Do not run Linux detection commands on Android.** Use JNI detection or return an empty environment; never call `resolvectl`/`nmcli` on a phone.
9. **Keep history rows sorted.** Ensure reopened history and saved entries preserve score order before selecting a winner.
10. **Handle Android setup failures.** Missing hostname, denied intent, and clipboard failure all produce a readable notice and manual steps.

## 16. Risks and mitigations

| Risk | Mitigation |
|---|---|
| No local Android SDK/NDK | Install the pinned SDK/NDK locally and in CI; build the APK before claiming Android support. |
| Waydroid image is newer than Android 8 | Cover the API 26–27 guide with unit tests; run the API 28+ path in Waydroid; mark API 26 runtime as untested unless hardware becomes available. |
| `cargo-apk` is deprecated | Pin 0.10.0 and NDK 27; keep `xbuild` as a documented fallback if the pinned tool fails. |
| JNI API changes/failures | Confine to `android.rs`; wrap every call; test the guide and fake host; fall back to manual instructions. |
| Private DNS hostname unavailable for a provider | Resolve through provider metadata; otherwise offer "switch to DoT" and explain. |
| Android 8 has no Private DNS | Explicit API-level branch and Wi-Fi DNS instructions. |
| eframe Android lifecycle/GLES issues | Use `glow` + native activity; test in CI APK and on a device; keep desktop build independent. |
| DoH root store on Android | Use webpki roots on Android; keep native certificates additive on desktop. |
| Large UI regression | Action-level kittest coverage, accessibility checks, touch-size checks, and both-layout tests. |
| APK signing secrets unavailable | CI validation uses the debug key; release fails clearly until secrets are configured. |
| Font licensing | Bundle only OFL fonts with licence files; fall back to egui fonts. |
